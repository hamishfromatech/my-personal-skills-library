## 2. Behavioral Psychology Findings

### The Hook Model for Developer Tools
Habit-forming products follow four steps: trigger, action, variable reward, investment.

**A-Coder Application**:
- **Trigger**: `a-coder .` command (external); "I need to fix this bug" (internal)
- **Action**: One-click project open, auto-detect language
- **Variable reward**: AI completions that surprise with elegant solutions; achievement badges; streak counters
- **Investment**: Custom themes, keybindings, plugin development

**Critical guardrail**: Variable rewards must teach, not addict. All engagement features require opt-out. No infinite scroll, no artificial scarcity.

### Cognitive Biases Most Relevant to DevTools
1. **IKEA Effect**: Users value what they partially build. Let users scaffold their own onboarding.
2. **Zeigarnik Effect**: Unfinished tasks drive return behavior. Progress bars for multi-step setup.
3. **Endowment Effect**: Customization before "ownership" increases retention. Save settings during trial.
4. **Social Proof**: "10,000+ developers using this template" increases trust.
5. **Authority Bias**: Expert-curated plugin collections signal quality.

### Dopamine Loop Design (Healthy)
- Release dopamine through contribution recognition, not manipulation
- Immediate PR feedback, mentorship badges, teaching loops
- Avoid: notification badges without limits, artificial urgency, surveillance-based "personalization"
