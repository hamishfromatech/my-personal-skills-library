## Key Findings

### Finding 1: Faros AI "Acceleration Whiplash" 2026 — Definitive Telemetry on AI's Downstream Damage (CRITICAL)

**Source:** Faros AI — "The AI Engineering Report 2026: The Acceleration Whiplash" (April 2026). Two years of telemetry. 22,000 developers. 4,000+ teams.

**Key data:**
- Code churn up 861% under high AI adoption (10× prior rate)
- Incidents-to-PR ratio up 242.7% (more than tripled)
- Bugs per developer up 54% (steepening, not flattening)
- Median time to first PR review up 156.6%; average time in review up 199.6%; median time in review up 441.5%
- PRs merged without any review up 31.3%
- Daily PR contexts per developer up 67.4%; work restarts up 13.8%
- 26% more in-progress tasks stalled 7+ days
- 80% of teams exceed 50% weekly active AI user threshold
- AI acceptance rate rose from 20% to 60%
- High-performing organizations (mature DevOps, high DORA) show the SAME downstream deterioration as everyone else

**Synthesis:** This is the largest quantitative study of AI's real engineering impact. The headline: AI is now the primary author of code in most organizations, and the system was never designed to absorb that volume. Volume is up. Quality is down. The gap is widening.

The "senior engineer tax" is the most politically significant finding: the most experienced engineers spend their most valuable hours unraveling plausible-looking AI code that should never have reached them. The 441.5% increase in median time in review means senior engineers are now primarily reviewers, not architects.

The 31.3% increase in unreviewed PRs suggests review capacity is collapsing under volume — not a deliberate policy choice, but a system failure.

**Novelty:** CRITICAL. No existing skill captures the 861% churn figure, the 242.7% incident ratio, or the explicit finding that "engineering maturity is not a shield." While `dora-ai-attribution-developer-experience-2026` exists and addresses DORA gaps, this data demands two new skills:
1. `cognitive-debt-audit` — a diagnostic and remediation framework for the six sources of cognitive debt
2. `harness-engineering-ai-agents-2026` — the Faros "harness engineering" framework (Agent = Model + Harness) with five production layers

### Finding 3: Developer Productivity Research Synthesis — SPACE, DevEx, and Bad Days

**Source:** Faros AI — "What Really Drives Developer Productivity? Insights from New Research" (April 2025/2026)

**Key data:**
- SPACE framework (2021): Satisfaction, Performance, Activity, Communication, Efficiency/Flow
- DevEx three dimensions (2023): Feedback Loops, Cognitive Load, Flow State
- Microsoft Engineering Thrive (32,000+ developers, 177 countries):
  - Flow time: ~50% more productivity with sufficient deep focus
  - Engaging work: 30% boost
  - Easy-to-understand code: 40% higher productivity; intuitive processes: 50% more innovation
  - Fast feedback: 20% higher innovation; fast answers: 50% less tech debt downstream
- "Bad Days" study (Jenna Butler/Microsoft + Purdue + UVic):
  - #1 cause: tooling and infrastructure issues (flaky tests, slow builds, broken CI/CD)
  - #2: process inefficiencies (unclear ownership, shifting priorities)
  - #3: team dynamics and communication
  - PR delay complaints correlated with 23.8% longer PR cycle times and 48.8% longer pickup times
  - Slow build complaints correlated with ~26% longer build times
  - Senior devs: frustration → disillusionment → quitting consideration
  - Junior devs: internalized blame → imposter syndrome

**Synthesis:** The Faros productivity synthesis is largely captured by existing skills (`developer-experience-devex-2026`, `self-determination-theory-developer-motivation`, `ai-brain-fry-defense`). The "bad days" study provides quantitative texture on the developer experience degradation but does not change structural understanding.

**Novelty:** Incremental. The 23.8%/48.8% PR delay data and the junior/senior differential response to bad days are useful additions but do not warrant new skills.

### 1. `cognitive-science-and-ux/cognitive-debt-audit/`
- **What:** Diagnostic and remediation framework for the six sources of cognitive debt created by AI-assisted workflows
- **Why novel:** No existing skill provides a structured audit tool for measuring the mental burden AI tools place on developers. This bridges the gap between productivity metrics and wellbeing. The six-source taxonomy (Verification Tax, Invisible-Decision Tax, Context-Reconstruction Tax, Switching Tax, Expertise-Erosion Tax, Addiction Tax) is original and grounded in 2026 research.
- **Key sections:** Six-source taxonomy, Cognitive Debt Scorecard (0–30 scale with severity bands), Team Diagnostic Protocol, Individual Recovery Plan (4-week program), Remediation Playbook with targeted interventions per source
- **A-Tech alignment:** Open-source AI ✓ (open-source dashboard plugin concept), Data privacy ✓ (local-only metrics), Financial freedom ✓ (sustainable productivity protects revenue), Practical implementation ✓ (full scorecard, recovery plan, measurement framework)

### 2. `ai-agents-and-workflows/harness-engineering-ai-agents-2026/`
- **What:** Five-layer harness engineering framework making AI agents reliable in production, derived from Faros AI 2026 research
- **Why novel:** Existing agent skills focus on trends (`agentic-coding-trends-2026`), commerce (`agentic-commerce-2026`), or reputation (`agent-reputation-identity-framework`). None provide a production-ready harness architecture with metrics for each layer. The Agent = Model + Harness distinction is the critical 2026 insight.
- **Key sections:** Five layers (Model, Orchestration, Context, Verification, Telemetry) with metrics, failure modes, and patterns per layer; production-grade build guide; measurement framework with 10 production metrics
- **A-Tech alignment:** Open-source AI ✓ (open-source harness toolkit), Data privacy ✓ (local-first telemetry options), Financial freedom ✓ (reduced production incidents = lower cost), Practical implementation ✓ (step-by-step build guide with targets)
