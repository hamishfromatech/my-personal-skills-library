# Five-Question Investment Decision Framework

## Source
Derived from the Seven Laws of Money framework by acquisition.com (Sharon Tseung / Alex Hormozi).

## The Five Questions
Before investing time, money, or resources in anything, ask:

1. **Can this compound?**
   - Is this a good long-term investment?
   - Will it grow in value over time without proportional ongoing effort?
   - *A-Tech filter:* Does this build brand equity, community, or IP that appreciates?

2. **Who has control?**
   - Is it you or someone else?
   - Can you influence the outcome?
   - *A-Tech filter:* Do we own the platform, the audience relationship, and the distribution?

3. **What happens if it fails?**
   - Do you get some or all of your money back?
   - Is the downside capped or unlimited?
   - *A-Tech filter:* Can we time-box or budget-cap the experiment? Is the core business protected?

4. **Is the upside meaningful and larger than the downside?**
   - Is this an asymmetric bet (capped downside, uncapped upside)?
   - Could this return 10x–100x, or is it a linear 1:1 payoff?
   - *A-Tech filter:* Are we building a platform/asset that scales, or trading time for money?

5. **Do you understand the risks?**
   - Can you clearly explain how the business works and what could go wrong?
   - Do you have insider knowledge or just public information?
   - *A-Tech filter:* Do we have domain expertise in this area, or are we guessing?

## Application Scoring Matrix

Use a 1–5 rating for each question. Minimum threshold: 20/25.

| Question | Weight | Score (1–5) | Notes |
|---|---|---|---|
| Can this compound? | 5x | | Long-term value creation |
| Who has control? | 4x | | Structural power over outcomes |
| What happens if it fails? | 4x | | Downside protection |
| Upside > Downside? | 5x | | Asymmetry |
| Do you understand the risks? | 4x | | Knowledge edge |
| **TOTAL** | **22x** | | **Target: ≥20/25** |

## A-Tech Decision Examples

### Example 1: Build A-Coder Enterprise Tier
| Question | Score | Rationale |
|---|---|---|
| Compound? | 5 | Code tools compound as the ecosystem grows |
| Control? | 5 | We own the product, roadmap, and distribution |
| Failure? | 4 | Core OSS remains; enterprise is additive |
| Upside? | 5 | Platform model = uncapped upside |
| Understand risk? | 4 | Deep domain expertise in dev tools |
| **TOTAL** | **23/25** | **GO** |

### Example 2: Launch a Podcast Network
| Question | Score | Rationale |
|---|---|---|
| Compound? | 3 | Content compounds, but discovery is uncertain |
| Control? | 3 | Platform algorithms control distribution |
| Failure? | 4 | Low cost to test, easy to shut down |
| Upside? | 3 | Ad/sponsorship model is linear, not exponential |
| Understand risk? | 3 | Not our core competency |
| **TOTAL** | **16/25** | **NO — unless pivoted to community-owned format** |

### Example 3: Acquire a Complementary OSS Project
| Question | Score | Rationale |
|---|---|---|
| Compound? | 5 | IP + community = compounding asset |
| Control? | 4 | We own it, but must maintain community trust |
| Failure? | 3 | Integration risk; reputation exposure |
| Upside? | 5 | Strategic fit multiplies both projects |
| Understand risk? | 4 | Strong technical understanding |
| **TOTAL** | **21/25** | **GO — with integration guardrails** |

## Anti-Patterns to Avoid

| Anti-Pattern | Law Violated | Example |
|---|---|---|
| Betting the empire on one launch | Law 6 | Spending entire marketing budget on one campaign |
| Diversifying into unknown markets | Law 7 | Launching products in categories we don't understand |
| Selling the core business for cash | Law 2 | Exiting a compounding asset for a one-time payout |
| Using leverage without collateral | Law 3 | Personal guarantees on speculative deals |
| Chasing linear returns | Law 5 | Consulting revenue without productizing the IP |
