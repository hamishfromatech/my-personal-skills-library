## Core Concept

Vibe coding is a software development practice coined by AI researcher Andrej Karpathy in early 2025 that shifts the primary developer role from writing code line-by-line to guiding an AI assistant through a conversational process. When applied responsibly, it preserves and enhances the developer's flow state — the psychological condition of deep focus where productivity, creativity, and satisfaction peak.

This skill focuses on the **responsible AI-assisted development** variant (not "pure" vibe coding which abandons code review). It treats the IDE as a flow-state preservation system, not merely a code generator.

## The Two Variants

### 1. "Pure" Vibe Coding (A-Tech: REJECT)
- Fully trusts AI output without review
- "Forgetting that the code even exists"
- Best for throwaway weekend projects only
- **Risk:** Technical debt, security vulnerabilities, skill atrophy

### 2. Responsible AI-Assisted Development (A-Tech: ADOPT)
- AI acts as powerful collaborator / pair programmer
- Human guides, reviews, tests, and owns final product
- Preserves learning and comprehension
- **Benefit:** 25-39% time recovery while maintaining code quality

## The Flow-State Preservation Framework

### The Four-Part Cycle (F2F — Flow-to-Feature)

1. **Tune In:** Set intention for the session. No tickets, just clarity. What does this feature want to be?
2. **Ride the Flow:** No distractions. Music, code, intuition. Short bursts, quick commits. AI handles syntax; human handles architecture.
3. **Review with Reality:** Refactor fast. Ask: "Does this make sense to someone else?" If not, re-vibe it.
4. **Log & Learn:** Capture insights in a lightweight digital garden. Vibe coding thrives on reflection.

### Key Behavioral Principles

| Principle | Mechanism | A-Coder Implementation |
|---|---|---|
| **Cognitive Ease** | Reduce mental load by handling syntax automatically | AI generates boilerplate; human focuses on logic |
| **Dopamine-Driven Feedback** | Immediate, visible results from natural language prompts | Live preview of generated code with one-click refinement |
| **Progressive Disclosure** | Surface complexity only when needed | Simple prompts by default; advanced options on request |
| **Flow Triggers** | Clear goals + immediate feedback + challenge-skill balance | Session intention setting + real-time execution + adjustable AI autonomy |
| **Agency Preservation** | Human remains the architect, AI the implementer | Explicit "architect mode" vs "implementation mode" toggle |

## Privacy-First Architecture

Unlike cloud-dependent vibe coding tools, A-Coder's implementation should:

- **Local-first processing:** AI inference runs on-device or private infrastructure
- **No code exfiltration:** Source code never leaves the user's environment
- **Transparent data flow:** User always knows what data goes where
- **Self-hostable:** Full stack can run on local hardware or trusted servers
- **Open-source models:** Uses open weights (Llama, Mistral, Granite) not proprietary APIs

## Practical Implementation for A-Coder

### IDE Features

| Feature | Description | Behavioral Trigger |
|---|---|---|
| **Flow Guardian** | Detects when developer is in flow state; suppresses non-critical notifications | Preserves deep work periods |
| **Vibe Mode** | Conversational code generation with natural language | Reduces cognitive load during exploration |
| **Reality Check** | Automated post-generation comprehension quiz | Ensures learning retention |
| **Two-Panel UI** | Generation panel + comprehension panel side-by-side | Generation-then-comprehension pattern |
| **Session Journal** | Auto-captures decisions and insights from each session | Builds institutional knowledge |
| **MCP Integration** | Model Context Protocol for external tool connections | Extends capability without leaving flow |

### Error State Design

When AI-generated code fails, the empathic error response:
1. **Acknowledge the disruption** ("This interruption breaks your flow — let's fix it fast")
2. **Explain without blame** (clear, jargon-free cause analysis)
3. **Offer the path back** (one-click fix + "return to flow" button)
4. **Log for learning** (capture error pattern for future prevention)
