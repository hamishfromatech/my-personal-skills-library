## CSA Research Note — Full Evidence

### The Framework Gap
- **NIST AI RMF 1.0** (July 2024 generative AI supplement, NIST AI 600-1): Four functions (Govern, Map, Measure, Manage), 12 generative AI risk categories. Actors are organizational entities. Citizen developers have no defined role.
- **OWASP LLM Top 10 (2025)**: Addresses developers, AppSec, CISOs, data scientists. OWASP's separate Citizen Development Top 10 and Low-Code/No-Code Top 10 predate vibe coding, not substantively updated.
- **CSA MAESTRO**: Seven-layer agentic AI threat modeling. Assumes security practitioner at design stage.
- **CSA AICM (July 2025)**: 243 control objectives, 18 domains, 5 actor roles. Citizen developer falls ambiguously between "Application Provider" and "AI Customer."

### Empirical Data
- **Escape.tech (Oct 2025):** Scan of 5,600 vibe-coded production applications. Zero had CSRF protection. Zero had standard security headers (CSP, HSTS, X-Frame-Options). Every application introduced SSRF vulnerabilities in URL-handling features.
- **GitGuardian (2026):** 28.65 million hardcoded secrets in public GitHub commits in 2025 (+34% YoY). Claude Code co-authored commits expose secrets at 3.2% vs 1.5% for human-written code. AI service keys: 1,275,105 leaked instances (+81% YoY).
- **Georgia Tech Vibe Security Radar (May 2025 launch):** CVEs from AI-generated code: 6 (Jan 2026), 15 (Feb 2026), 35 (Mar 2026) — more in Q1 2026 than all of 2025.
- **IBM Cost of Data Breach 2025:** 63% of 600 surveyed orgs had no AI governance policies. Shadow AI breaches cost $670K more than average ($4.63M average). 20% of orgs already breached via shadow AI.
- **IDC 2025:** 56% of employees use unauthorized AI tools; only 23% use IT-governed alternatives.
- **Apiiro (2025):** 322% more privilege escalation paths in AI-generated code. 153% more design flaws.
- **Gartner (2025):** 70% of new enterprise applications built using low-code/no-code by 2025. 60% of new code AI-generated by end of 2026.

### Documented Breaches
- **Moltbook:** Vibe-coded social network. Supabase API key in client-side JS. Row Level Security completely disabled. 1.5M API authentication tokens + 35K emails exposed within 3 days of launch. (Wiz Security, 2026)
- **Cal AI:** 14.59 GB, ~3.2M user records exposed via unauthenticated Google Firebase backend. (Kiteworks, March 2026)
- **Lovable (CVE-2025-48757):** Supabase projects had insufficient Row-Level Security. AI generated database layer but not access controls. 170+ production applications exposed. Pre-November 2025 Lovable projects accessible to other users — one account could view another's source code, database credentials, customer data. (Matt Palmer / The Register, 2025-2026)
- **Base 44:** Flaw exposed private enterprise applications. (Security Week)

### Shadow Operations
- Traditional shadow IT: employees adopting unapproved vendors of approved-category services. Response: discover, block, redirect.
- Shadow operations: employees building autonomous, data-processing applications on approved enterprise platforms (Power Platform, Salesforce, ServiceNow). Platform is sanctioned; specific application is not. Standard playbook doesn't apply.
- **CIO Magazine (2026):** "Shadow AI morphs into shadow operations."

## Unit 42 SHIELD Framework — Full Detail

### Root Causes of Vibe Coding Risk
1. **Models prioritize function over security:** AI agents optimized to provide working answers fast, not to ask security questions. Insecure by default. Security scanning/judge agents are elective.
2. **Critical context blindness:** AI agent lacks situational awareness (e.g., prod vs. dev environment distinction).
3. **Phantom supply chain risk:** AI hallucinates libraries/packages that don't exist → unresolvable dependencies.
4. **Citizen developers and developer over-trust:** Non-developers lack training in secure code. Code looks correct and works → false sense of security → vulnerabilities due to lack of change control and secure code review.

### Documented Incidents (Unit 42)
1. Sales lead application breached because vibe coding agent neglected authentication and rate limiting controls.
2. Indirect prompt injection allowed malicious command injection via untrusted content → arbitrary code execution + data exfiltration.
3. Authentication bypass by displaying application's publicly visible ID in API request.
4. AI agent deleted entire production database despite explicit instructions to freeze production changes.

### SHIELD Controls
- **S — Separation of Duties:** Restrict agents to dev/test environments only. No over-aggregated privileges.
- **H — Human in the Loop:** Mandatory secure code review + PR approval for critical functions. Vital for non-developers.
- **I — Input/Output Validation:** Prompt partitioning, encoding, role-based separation (input). SAST after development, before merge (output).
- **E — Enforce Security-Focused Helper Models:** External/independent helper models for SAST, secrets scanning, security control verification. Prior to deployment.
- **L — Least Agency:** Minimum permissions/capabilities. Restrict sensitive file access. Guardrail destructive commands.
- **D — Defensive Technical Controls:** SCA before consumption. Disable auto-execution. Human-in-the-loop + helper agent involvement in deployment.

## CSA Resource Alignment

- **CSA AI Controls Matrix:** 243 control objectives, 18 domains. Natural candidate for citizen developer extension.
- **CSA MAESTRO:** Seven-layer model. Layer 3 (Agent Frameworks) and Layer 7 (Agent Ecosystem) map to citizen-built agentic apps.
