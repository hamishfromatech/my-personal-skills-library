# Application Playbook: Step-by-Step Worksheets

## Worksheet 1: The Fluency Audit

Use this to audit any existing page, email, or document.

### Section A: Clarity (The 5-Second Test)
- [ ] The main promise is visible in the first headline
- [ ] The headline contains no jargon that a non-expert would not understand
- [ ] A visitor can answer "What is this?" and "What do I do next?" within 5 seconds
- [ ] The CTA uses an action verb and names the outcome
- [ ] There is only one primary CTA above the fold

### Section B: Consistency (The Mere-Exposure Check)
- [ ] The terminology matches our lexicon (see Be Practical glossary)
- [ ] Colors, fonts, and spacing match the design system
- [ ] Tone matches the established voice (direct, practical, scar-informed)
- [ ] If this is a sequence (email series, onboarding flow), the rhythm is predictable

### Section C: Cognitive Load (The Brain-Friendliness Score)
- [ ] No paragraph exceeds 4 lines on mobile
- [ ] Every visual element supports comprehension (no decoration without function)
- [ ] Numbered or bulleted lists break up dense information
- [ ] Technical terms are defined on first use, then used consistently
- [ ] White space is used actively to create breathing room

### Section D: Friction (The Action-Ease Test)
- [ ] The next step requires no more than 2 clicks or inputs
- [ ] The user knows exactly what will happen after they act
- [ ] No surprise requests for data (especially before value is delivered)
- [ ] Error states are anticipated and guided with plain language

## Worksheet 2: The Scars-Not-Wounds Filter

Apply this to any story, testimonial, or piece of vulnerability you plan to publish.

| Criterion | Scar (Ship It) | Wound (Revise or Hold) |
|-----------|---------------|------------------------|
| **Resolution** | The experience has a clear lesson or outcome | The experience is still raw and unresolved |
| **Agency** | The sharer took action and changed something | The sharer is still trapped in the situation |
| **Purpose** | Shared to teach, warn, or connect | Shared to extract sympathy or urgency |
| **Audience benefit** | The reader gains a framework, warning, or hope | The reader feels burdened or manipulated |
| **Consent** | The sharer is fully ready to tell this story | The sharer feels pressured to disclose |

**Rule**: Pass at least 4 of 5 to ship. If "Resolution" fails, do not ship.

## Worksheet 3: Curiosity-Gap Headline Formula

Template: **[Specific Subject] + [Specific Gap] + [Attainable Promise]**

### Examples for A-Coder
- Weak: "A-Coder makes coding easier."
- Strong: "The one A-Coder setting that eliminates 90% of repetitive boilerplate (takes 10 seconds)."

### Examples for Be Practical
- Weak: "Learn marketing from our book."
- Strong: "The 'scars not wounds' email template that doubled our reply rate—and why almost everyone gets step 2 wrong."

### Examples for Builder's Club
- Weak: "Join our open-source community."
- Strong: "The 3-line contribution that earned one Builder a $15K consulting contract (and how to do it in under 5 minutes)."

## Worksheet 4: The First-Hour Ownership Ladder

Design the first hour of a new user's life so they build something they value.

### For A-Coder
1. **Minute 0-2**: Open the app. See a working project (not a blank screen).
2. **Minute 2-10**: Make one visible change. Run it. See the result.
3. **Minute 10-30**: Save it. Name it. It is now "their" project.
4. **Minute 30-60**: Share it or export it. They have created something they can show.

### For Builder's Club
1. **Minute 0-5**: Land on the README. See exactly how to join.
2. **Minute 5-15**: Make a contribution that is guaranteed to be accepted (e.g., fix a typo, add a resource, answer a question).
3. **Minute 15-30**: See their name in the contributors list or receive a public thank-you.
4. **Minute 30-60**: Receive a personalized welcome message referencing their specific contribution.

## Worksheet 5: Privacy-First Social Proof

Since A-Tech values data privacy, social proof must be built without invasive tracking.

| Tactic | Implementation | Privacy Level |
|--------|---------------|---------------|
| **Contributor walls** | Public GitHub contributor graphs, named testimonials | Fully public, consensual |
| **Playbook outcome stories** | Community members describe results in their own words | Zero-party data (voluntarily shared) |
| **Usage milestones** | "1,000 developers" (aggregated, anonymized) | Anonymous, no individual tracking |
| **Real screenshots** | Unedited images of real projects, real workflows | Consensual, no tracking required |
| **Live community events** | Office hours, AMAs, public Discord threads | Transparent, real-time, no profiling |

**Avoid**: Pixel-based retargeting, hidden tracking, scraped social proof, fake testimonials, inflated numbers.
